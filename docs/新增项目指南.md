# 新增项目指南

面向“往 `stem-education/` 里再加一个 STEM 项目”的操作清单。整套流程约 10 分钟。

## 一、创建骨架

```bash
cd stem-education

# 推荐：用脚本（自动复制模板、替换占位符、提示登记索引）
./scripts/new-project.sh line-follower-car "循迹小车"

# 或手动
cp -r templates/project-template projects/line-follower-car
```

脚本会做的事：复制 `templates/project-template/` → `projects/<目录名>/`，把模板里的 `{{PROJECT_NAME}}` / `{{PROJECT_SLUG}}` / `{{PROJECT_ID}}` 替换成实际值，并打印后续待办。

## 二、填写必备内容（按顺序）

| 步骤 | 文件 | 要填什么 |
|---|---|---|
| 1 | `projects/<项目名>/project.yaml` | 项目编号、中文名、状态、标签、平台、许可 |
| 2 | `projects/<项目名>/README.md` | 定位一句话、能力参数、当前进度、快速开始、目录导航 |
| 3 | `projects/README.md` | **索引表新增一行**（编号、项目名、方向、状态、入口链接） |
| 4 | `docs/01-项目简介.md` | 是什么、教学价值、目标人群、能达到什么效果 |
| 5 | `docs/02-选型与BOM.md` | 版本/型号差异、采购渠道、参考价、替代方案 |
| 6 | `docs/99-参考资源.md` | 官方仓库、Wiki、视频、社区帖（含链接与访问日期） |
| 7 | `enclosure/print-notes.md` | 材料、层高、填充、支撑、后处理、装配顺序 |
| 8 | `firmware/README.md`、各 `software/*/README.md` | 工具链版本、编译/安装、运行、验证方法 |

## 三、资料归档原则

1. **先登记链接，再决定是否入库文件。**
   - 官方仓库/文档 → 记在 `docs/99-参考资源.md`
   - 需要离线可用的关键文件（原理图 PDF、BOM、装配图）→ 放对应 `hardware/`、`enclosure/` 目录
2. **大文件不进 Git**：> 50 MB 的 STEP/STL/视频/数据集 → 走 Git LFS 或网盘，见 `大文件与Git-LFS.md`。
3. **截图与照片**放 `resources/`，并在该目录 `README.md` 里写一句它对应哪一步。
4. **第三方代码**：优先用 Git Submodule 或只记录「上游 + 指定 commit/tag + 本地改动说明」，避免整包复制导致后续无法合并上游更新。

## 四、状态与版本维护

- 项目状态取值：`资料整理` → `复刻中` → `已完成` → `维护中` / `已归档`，写在 `project.yaml` 与 `project.yaml` 对应的索引表里。
- 每次有实质进展（改硬件版本、换电机、跑通新流程），在 `CHANGELOG.md` 追加一条：

```markdown
## [0.2.0] - 2026-10-19
### 变更
- 末端关节增加线束约束件
### 原因
- 实测线束在极限姿态下干涉
### 影响
- enclosure/stl 中 3 个文件替换，需重新打印
```

## 五、提交约定

- 一次提交只做一件事，提交信息用中文、带项目 scope：

```
feat(rebot-devarm): 补充 B601-DM 版本 BOM 与采购链接
docs(rebot-devarm): 新增组装教程第三章“标定”
enclosure(rebot-devarm): 更新末端关节线束约束件至 v1.1
```

- **不要**把课程里学生的个人数据、真实账号、内网 IP、密钥提交进仓库。

## 六、教学线：六维拆解 + 三份教学材料（skill）

工程文档补齐后，用本仓库内置 skill 生成"零基础家长带小学生从零入门"这一层：

```
.trae/skills/stem-project-onboarding/SKILL.md
```

它会做两件事：

1. **六维拆解**（硬件电子 / 结构外壳 / 固件 / 上位机软件 / 算法代码 / 资料与生态），逐维回答"门槛在哪、能不能买成品或外协绕过、最容易卡在哪、到底怎么做出来（嘉立创 PCB 打样/SMT、3D 打印代做、代焊代烧等）"；
2. **产出工程文档 + 三份教学材料**：
   - 工程文档（六维拆解分析）：`docs/01-项目简介.md` ~ `05-教学与课程.md` 与 `99-参考资源.md`（增量补齐，不推倒重写）；
   - ① 家长实现手册：`docs/家长实现/`（总纲与路线图 / 六维拆解总表 / 里程碑与任务卡 / 家长话术与提问卡 / 验收与展示 / 安全与工具采购清单），**实现导向、简洁**，只写"怎么做到"；
   - ② 儿童课程（即"PPT"）：**按课时分目录** `docs/儿童课程/第NN课-课题/{课件.md, 图/, 知识卡/, README.md}`，`课件.md` 构建成同目录 `课件.html` 可全屏放映（`Ctrl+P` 可导出 PDF 当讲义）；
   - ③ 儿童知识卡：`docs/儿童课程/第NN课-课题/知识卡/NN-主题.md`，一个原理点一张（现象 → 猜 → 验证 → 术语 → 还见过），可打印给孩子；**随课时分发**，拷走一课目录即含本课的全部卡。

   > 不再产出 `docs/备课文案/`（逐字稿）。家长要的话术要点写在 `家长实现/03-家长话术与提问卡.md` 与课件讲者备注里。

生成骨架：

```bash
S=.trae/skills/stem-project-onboarding
$S/scripts/scaffold_family_guide.sh <项目目录名>        # docs/家长实现/
$S/scripts/scaffold_teaching_materials.sh <项目目录名>  # docs/儿童课程/第NN课-课题/{课件.md,图/,知识卡/}
python3 $S/scripts/build_slides.py projects/<项目目录名>/docs/儿童课程/*/课件.md --strict   # 课件 → HTML（零依赖）
```

三条脚本都默认不覆盖已存在文件（便于增量补教学线），需要覆盖加 `--force`。骨架生成后必须把占位符 `__` 填成实际内容，并按 skill 的自检清单逐条打勾再提交。

约定：

- 任务卡按 **≤25 分钟一个动作单元** 切分，每档参与度分 L1 观察 / L2 协作 / L3 独立，家长按孩子实际水平选档；
- 危险步骤（焊接、220V、锂电池、上电抱闸、金属加工、激光）一律家长执行并标 ⚠️；
- 每个术语首次出现必须给"生活类比 + 一句话解释"；
- 面向孩子：里程碑改叫关卡、每 3 张卡一次展示时刻、一句话 ≤12 字、每张知识卡走"现象 → 猜 → 验证 → 术语 → 还见过"五步；
- 写实现路径时先说清"买成品 / 找代做 / 自制"三选一，自制件要给能下单的参数（层数、板厚、材料、填充、公差）；
- 不写未验证的精度/性能宣传，未实测的标 `待验证`。
