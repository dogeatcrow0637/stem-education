# 目录规范

本文件定义 `stem-education/` 下所有项目的统一结构。目的是让每个项目**长得一样**，任何人换个项目都能立刻找到图纸、代码和文档。

## 0. 一眼看懂的分工

```
硬件图纸 → hardware/      结构外壳 → enclosure/
主控程序 → firmware/      电脑软件 → software/
算法实验 → code/          教学文档 → docs/
素材外链 → resources/
```

判断一个文件放哪：**它是给谁用的？**

| 问题 | 答案 | 位置 |
|---|---|---|
| 要焊接、要采购吗？ | 是 | `hardware/` |
| 要打印 / 要装配结构吗？ | 是 | `enclosure/` |
| 跑在单片机、主控板上吗？ | 是 | `firmware/` |
| 跑在 PC、笔记本、开发机上吗？ | 是 | `software/` |
| 是算法、脚本、模型训练代码吗？ | 是 | `code/` |
| 是给人看的说明、教案、踩坑记录吗？ | 是 | `docs/` |
| 是图片、视频、演示素材、外部资料存档吗？ | 是 | `resources/` |

## 1. 顶层目录

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `docs/` | 项目简介、选型与 BOM 说明、组装与调试步骤、软件环境搭建、踩坑记录、参考资料索引 | 生成物、临时笔记 |
| `hardware/` | 原理图、PCB、接线图、BOM 表、数据手册 | 结构件（放 `enclosure/`） |
| `enclosure/` | 外壳/支架的 3D 源文件与可打印文件、打印参数说明 | 电子部分图纸 |
| `firmware/` | 主控/MCU/驱动板固件源码、编译脚本、烧录说明 | PC 端程序 |
| `software/` | 上位机、SDK、工具链（见 §3） | 固件源码 |
| `code/` | 算法、视觉、轨迹、数据处理的实验代码与 notebook | 成品软件界面 |
| `resources/` | 图片、视频、BOM 截图、外部资料备份 | 源码 |

## 2. 各目录细则

### docs/

- 文件用 **`NN-中文标题.md`** 排序，`NN` 从 `01` 开始：
  - `01-项目简介.md`——是什么、能做什么、教学价值、目标人群
  - `02-选型与BOM.md`——版本差异、选型对比、采购渠道与价格
  - `03-组装与调试.md`——分步骤装配、校准、通电自检
  - `04-软件环境.md`——操作系统、依赖版本、一键安装脚本入口
  - `05-教学与课程.md`——课时安排、实验任务、考核点
  - `99-参考资源.md`——官方仓库、Wiki、视频教程、社区链接
- `家长实现/`——面向零基础家长的六个固定文件（总纲与路线图 / 六维拆解总表 / 里程碑与任务卡 / 家长话术与提问卡 / 验收与展示 / 安全与工具采购清单），由 `.trae/skills/stem-project-onboarding` 生成骨架，见 `新增项目指南.md` 第六节。工程内容放上一条的 `NN-*.md`，教学与陪伴内容放这里。
- `儿童课程/`——**按课时分目录**：`第NN课-课题/{课件.md, 课件.html, 图/, 知识卡/, README.md}`，一课一个自包含材料包（拷走这一课就能上课）；`儿童课程/README.md` 是课程总览与知识卡全集索引。课件是 Marp 风格 Markdown（一课时一个 `课件.md`），构建出的同名 `.html` 可直接全屏放映；知识卡 `NN-主题.md` 一个原理点一张，给孩子看、可打印。骨架由 skill 的 `scaffold_teaching_materials.sh` 生成、`build_slides.py` 构建课件。本仓库不产出 `备课文案/`。
- 每个文档头部建议写：**适用版本 / 最后更新日期 / 前置条件**。
- 涉及硬件操作的危险步骤（通电、上电抱闸、高压、激光、加热）必须单独标注 ⚠️。

### hardware/

| 子目录 | 内容 | 推荐格式 |
|---|---|---|
| `schematic/` | 原理图、PCB 工程、接线图 | `.pdf`（便于阅读）+ 源文件（`.SchDoc`/`.kicad_sch`/`.epro`） |
| `bom/` | 采购清单 | CSV/XLSX，字段：编号、名称、规格型号、数量、参考价、采购链接、替代型号 |
| `datasheet/` | 芯片、电机、传感器手册 | `.pdf`，文件名带型号 |

约定：**接线图必须同时给“图”和“表”**（表格列出每个端子的信号名、线色、对端）。

### enclosure/

| 子目录 | 内容 |
|---|---|
| `step/` | 可编辑源文件：STEP/STP、F3D、SLDPRT、FreeCAD |
| `stl/` | 可直接切片：STL、3MF |
| `print-notes.md` | 打印与装配说明（见下） |

`print-notes.md` 必填项：

1. **材料**（PLA / PETG / ABS / TPU / 尼龙 + 是否需退火）
2. **参数**：层高、壁厚（圈数）、填充率与图案、支撑策略、打印朝向
3. **后处理**：去支撑、攻丝、热熔铜螺母规格、胶合方式
4. **装配顺序**与易错点（对称件如何区分、螺丝规格与扭矩）
5. **版本差异**：哪个版本改了哪个件（对照 `CHANGELOG.md`）

### firmware/

- 一个主控一个子目录，例如 `firmware/main-board/`、`firmware/gripper/`。
- 必须有 `README.md`：开发板型号、工具链版本、编译命令、烧录命令、验证方法。
- 第三方 SDK/库用子模块或 `libs/` 目录，并在 README 写明来源与版本。
- **不要提交**编译产物（`.hex`、`.bin`、`.elf` 已被 `.gitignore` 忽略）。

### software/

| 子目录 | 内容 | 例子 |
|---|---|---|
| `host/` | 上位机：图形控制台、状态监控、参数配置 | Qt/PySide/Electron/Web 界面 |
| `sdk/` | 对外二次开发接口 | Python 包、C++ 库、ROS 包 |
| `tools/` | 开发机工具：烧录、标定、仿真、环境初始化 | `install.sh`、`calibrate.py` |

约定：

- 每个子项目自带 `README.md`（依赖、安装、运行、常见问题）。
- 依赖锁定：Python 用 `requirements.txt`/`pyproject.toml`；Node 用 `package-lock.json`；写明**已验证的操作系统版本**。
- 硬件相关软件建议注明**是否需要物理机**（虚拟机/容器可能因 USB、实时性不可用）。

### code/

- 按主题分子目录，例如 `code/vision-grasp/`、`code/traj-plan/`、`code/vla-finetune/`。
- 实验代码建议配 `notebooks/` 与 `scripts/`，并说明**数据集来源与存放位置**（大数据集不入库）。

### resources/

- 只放中小体积素材（图片、图表、切片截图、演示动图）。
- 单个文件 > 50 MB 的（视频、大模型、完整数据集）**不入 Git**，在本目录的 `README.md` 里登记外链与校验值。

## 3. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 项目目录 | 全小写 + 短横线 | `rebot-devarm`、`line-follower-car` |
| 文档 | `NN-中文标题.md` | `03-组装与调试.md` |
| 代码目录/文件 | 英文，小写下划线或短横线，跟随该语言习惯 | `grasp_node.py`、`traj_planner/` |
| 3D 打印件 | `件名_版本_数量.stl` | `base_v1.1_x1.stl` |
| BOM | `bom_<版本>.csv` | `bom_b601-dm_v1.1.csv` |
| 图片 | `描述_版本.png` | `wiring_power_v1.1.png` |

## 4. 每个项目 README.md 的必备小节

```markdown
# 项目名（中文名）
> 一句话定位

## 这是什么
## 能力与参数
## 当前进度        <- 状态：资料整理 / 复刻中 / 已完成 / 维护中
## 快速开始        <- 最短路径：买什么 → 打印什么 → 跑什么命令
## 目录导航        <- 各目录一句话说明 + 链接
## 已知问题与踩坑
## 许可与致谢
## 参考资料
```
