# 六维拆解参考（Step 2 用）

拆解的目标不是"把资料搬一遍"，而是**回答三个问题：门槛在哪、能不能绕开、容易卡在哪**。每维都得答完。

## 通用方法

### 事实源优先级（从高到低，冲突时取前者）

1. 官方仓库的代码、配置、BOM 源文件（能被验证的东西）
2. 官方文档 / Wiki / 发布说明
3. 器件数据手册（电压、电流、扭矩、引脚）
4. 已整理好的 BOM 与采购页（注意：商家页参数常有夸张）
5. 社区复刻帖、视频（只能作线索，参数回到 1–3 核实）
6. 电商客服口径（仅用于采购便利性，不作为技术依据）

> 每条写进文档的参数后面标来源；查不到的写 `待确认`。**宁可留空，不要编造。**

### 每维的输出格式

```
维度：① 硬件电子
- 清单：（型号 + 数量 + 参考价 + 采购渠道 + 替代型号）
- 供电与余量：（电压 / 峰值电流 / 电源额定 / 余量倍数）
- 门槛：最难的三个动作 = ...（需要什么技能）
- 降级路径：哪些可以买成品 / 外协 / 用别人编译好的东西（含费用量级与渠道）
- 卡点：最可能卡住的地方 + 前置检查手段
- 实现路径：买成品 / 代做 / 自制 三选一 + 下单参数（板厚/材料/填充/公差）+ 谁做 + 交期
- 谁做：家长（L1/L2/L3 三档分别要做什么）
```

> 实现路径的写法（打样参数、代做渠道、外协话术、收货验收、成本周期量级）见 `可实现路径与外包.md`；本文不重复。**先模块堆叠跑通 MVP，最后才考虑自制板。**

## 维度 ① 硬件电子 → `hardware/`

**提取清单**

- 主控 / 驱动板型号，固件是否开源、烧录接口（USB / SWD / 串口）
- 执行器：电机型号、额定与峰值电流、是否带减速器、**是否有抱闸**（无抱闸的通电前必须支撑）
- 传感器：接口类型（I2C / SPI / 模拟 / 脉冲）、供电电压、是否需要电平转换
- 电源：电压（12V/24V/48V）、峰值电流、接口类型（XT30 / DC 头 / 端子台）、是否需自行配适配器
- 线束：是否包含在套件内、需要自制哪些、端子压接工具是否有
- 接线：每个端子的信号名、线色、对端

**判定标准**

- 电源额定电流 ≥ 所有负载峰值之和 × 1.5（除堵转电流）；不满足就写"必须换电源"。
- 电机/加热/激光类必须单列"堵转/短路会发生什么"。
- 有 CAN/RS485/差分信号的项目，必须写清终端电阻与共地要求。

**常见坑**

- 官方 BOM 与出货实物不一致（镭雕、打印件替换、线束定制）→ 采购前逐项比对。
- 电机驱动与电机是同厂但不同协议版本（如两版电机），固件不能混用。
- 只算电机成本、不算电源/线束/端子/工具（常占总价 20–40%）。
- 板子标注 5V 但传感器要 3.3V，直接接会烧。

## 维度 ② 结构外壳 → `enclosure/`

**提取清单**

- 打印件：件名、数量、材料建议、是否需要支撑、打印时长与耗材量
- 金属加工件：材质、工艺（激光切割/CNC/手钻）、是否可外协、单价
- 标准件：螺丝规格（M2/M2.5/M3 + 长度）、螺母（热熔铜螺母规格）、轴承、卡簧
- 打印尺寸是否超过常用机型（220×220mm 是常见上限），超了要拆件或找代打
- 装配顺序与方向性（对称件怎么区分、哪些件必须先装、哪些后装）

**判定标准**

- 每个运动部件必须有"干涉检查"结论：极限位是否会撞、线束会不会被夹。
- 承力件（悬臂/关节）明确材料与填充率下限；PLA 在长期受力下会蠕变。

**常见坑**

- 打印公差：孔位偏小 0.1–0.2mm 是常态，需预留攻丝或用热熔铜螺母。
- 后装件被忘了先装（拆一半重来，最容易劝退孩子）。
- 打印件当结构件用却没有加强筋，一受力就断。
- 只给 STL 没给打印参数（材料/填充/朝向）→ 代打店随手打，装不上。
- 孔位不留公差（±0.2mm）→ 铜柱敲不进去，或间隙大得晃。

## 维度 ③ 固件 → `firmware/`

**提取清单**

- 开发板型号与工具链（Arduino IDE / PlatformIO / Keil / ESP-IDF / 厂商 IDE）与**具体版本**
- 编译命令、烧录命令、烧录时是否需要按住 BOOT / 断电器件
- 引脚定义表（谁接哪个引脚，冲突了怎么办）
- 是否需要标定（电机零位、传感器偏移、PID 参数），标定步骤
- 验证方法（烧完怎么知道成功了：串口打印 / LED / 蜂鸣 / 动作）

**判定标准**

- 必须能给出**一句话验证**："烧录成功后，打开串口应看到 `...`"。
- 依赖库必须锁版本（库的新版经常改 API，是新手第一大坑）。

**常见坑**

- 烧录前不断开电机/舵机电源 → 上电瞬间乱动伤人。
- 串口被上位机占用导致烧录失败（现象像"板子坏了"）。
- 芯片需要额外配置（ESP32 分区表、STM32 时钟树）却只在官方 issue 里提过。

## 维度 ④ 上位机软件 → `software/`

**提取清单**

- 操作系统与版本（很多项目只支持 Ubuntu 物理机，**虚拟机因 USB 直通与实时性不可用**）
- 运行时与版本（Python / Node / ROS 发行版）、依赖安装方式（pip / apt / conda / 一键脚本）
- 设备权限（串口 `dialout`、USB udev 规则、CAN 接口 `ip link` 配置、实时内核）
- 启动顺序（先起哪个后起哪个）、配置文件位置、日志位置
- 是否需要联网/账号/授权

**判定标准**

- 必须给出"从零到能启动"的最短命令序列，且每条命令写明预期输出。
- 涉及内核模块 / udev / 权限的项目，必须写回滚方法。

**常见坑**

- `requirements.txt` 没锁版本，半年后装不上。
- 需要改系统配置（udev、内核参数、串口权限）却没写，导致"我这儿就是不行"。
- 用 Docker 跑需要 USB/CAN 的项目，权限与设备映射没打通。

## 维度 ⑤ 算法代码 → `code/`

**提取清单**

- 依赖的算力（是否需要 NVIDIA GPU、显存下限）、模型来源与许可
- 数据集来源、体积、获取方式（很多数据集要申请或需要外网）
- 是否可降级：能不能用"固定动作回放 / 预设轨迹 / 开源预训练权重"替代训练
- 可视化入口（有没有 GUI / 网页 / 视频输出，孩子能看到什么）

**判定标准**

- 给孩子看的部分**必须有可视结果**；纯数字指标的算法环节一律降级或放进 L3 挑战档。
- 需要联网下载大模型的环节，写清体积与备用方案（否则第一天就卡在下载）。

**常见坑**

- 训练链路对新手不友好（要自己标数据、要 GPU）→ 教学线里应默认跳过，放到 M4 挑战。
- 仿真环境与真机行为有差异，别承诺"仿真跑通就一定能上真机"。

## 维度 ⑥ 资料与生态 → `docs/99-参考资源.md`

**提取清单**

- 官方仓库（含国内镜像）、Wiki、文档站、视频教程、社区群/论坛
- 许可：硬件与软件分别是什么，是否允许商用，是否有"非商业"条款
- 资料失效风险：链接是否长期稳定、是否有本地存档（`resources/`）
- 官方是否声明"公布资料 ≠ 出货版本"

**判定标准**

- 每条资源写**访问日期**与"它解决什么问题"。
- 许可里出现 NC / 非商业 / 需署名 的，在 `project.yaml` 与 README 双处登记。

## 横向维度（贯穿六维，不单独成目录，但必须写进文档）

| 横向维度 | 要产出什么 |
|---|---|
| 采购与预算 | MVP 第一批（能跑通最小闭环）+ 后续可选；含替代型号与渠道；标注可能的外协费 |
| 安全 | 危险源清单（高压/锂电/烙铁/热熔胶/旋转件/激光/夹伤），谁执行、防护、出错收场 |
| 工具与场地 | 必备工具、耗材、桌面要求（防静电、防火垫、收纳、断电习惯） |
| 法律与合规 | 许可限制、无线电频段与功率（无线项目）、儿童使用年龄提示 |
| 可复现性 | 版本号、commit/tag、参数、照片与录屏存档位置（`resources/`） |

## 家长的技能矩阵（用来判定门槛与降级路径）

| 技能 | 典型环节 | 零基础家长的替代方案 |
|---|---|---|
| 焊接 | 接线、换插头 | 买带端子的成品线束 / 用免焊端子 / 找创客空间代焊 |
| 烧录 | 固件上板 | 买已烧录好的成品模块 / 求社区代烧（给红包即可） |
| 命令行 | 环境搭建 | 用官方一键脚本 / Docker 镜像；仍不行就找 Linux 用户远程协助 |
| 3D 打印 | 外壳 | 找代打服务（按克计价）/ 淘宝打印店 / 学校创客教室 |
| 机械加工 | 金属件 | 直接买成品金属件套件 |
| 调试与排错 | 全线 | 这是**唯一无法外包的部分**，必须在任务卡里给出可执行的排查顺序 |

## 拆解时的常见判定错误

1. 把"官方宣传参数"当实测值写进教学文档。
2. 只列 BOM 不算电源与线束成本。
3. 假设家长能烧录 / 能焊接，不给替代路径。
4. 把"能跑通仿真"写成"能上真机"。
5. 忽略"无抱闸电机断电下落"这类**非电子**的物理风险。
6. 里程碑按工程顺序排（先装完再通电），而不是按"孩子多久能看到反馈"排。
