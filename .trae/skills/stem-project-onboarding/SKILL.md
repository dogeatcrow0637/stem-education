# STEM 项目拆解 → 可执行教学材料

## 0. 唯一事实源（先读，不要在本 skill 里重写目录结构）

- `docs/目录规范.md`：目录分工、命名、每个 README 必备小节
- `docs/新增项目指南.md`：建档八步与提交约定
- `templates/project-template/`：新建项目骨架

本 skill 只补最薄的一层：把工程资料变成**家长能带着做、孩子愿意看**的材料。

仓库根 = 本文件向上三级（`SKILL.md` → `skills/` → `.trae/` → 仓库根）。所有路径相对仓库根。

## 1. 快启动

```bash
S=.trae/skills/stem-project-onboarding
$S/scripts/scaffold_family_guide.sh <slug>          # docs/家长实现/ 六个文件
$S/scripts/scaffold_teaching_materials.sh <slug>    # docs/儿童课程/第NN课-课题/ 骨架（课件 + 图/ + 知识卡/ + 课时 README）
python3 $S/scripts/build_slides.py projects/<slug>/docs/儿童课程/*/课件.md --strict   # 课件 md → 可放映 HTML
```

三个脚本都支持 `--repo <仓库根>`（默认自动向上查找）与 `--force`（默认不覆盖已存在文件，便于增量补线）。`build_slides.py` 加 `--strict` 时有提示即返回非零，可当自检门禁。

| 输入形态 | 典型说法 | 起始动作 |
|---|---|---|
| A 纯外部资料 | "这个开源项目帮我拆一下" + 链接 | `./scripts/new-project.sh <slug> "<中文名>"` 建档后再拆 |
| B 已有项目目录 | "给 line-follower-car 补教学线" | 读 `projects/<slug>/`，增量补齐（见 §7） |
| C 只有实物/一堆料 | "朋友给了我一堆零件" | 先做物料反推：型号照片 → 数据手册 → 确定是哪套开源项目 |

参数一律取默认值，缺省不追问，并在产出里写明假设：学段**分层自适应**（每个环节给 L1/L2/L3 三档）；家长**零基础**（不会焊接/不写代码）；预算**先买最小可跑闭环**；无实物时把"选型采购"作为 M0 而非前置杂事。

**最多问 3 个问题**：项目来源 / 有没有实物 / 预算上限。

## 2. 工作流（六步）

1. **建档与事实采集**：确认 `project.yaml`、`README.md` 存在。采集可验证事实（电压电流、通信方式、主控、工具链、系统要求、轴数/扭矩/负载、许可），每条标来源，查不到写 `待确认（来源：无）`，官方宣传值标 `宣传值，需实测`。
2. **六维拆解**：按 §3，每维回答四问（门槛 / 降级路径 / 卡点 / 实现路径）。
3. **实现路径落地**：按 §4 把每个环节定成"买成品 / 找代做 / 自制"三选一，写成可下单或可动手的参数。**默认先模块堆叠跑通 MVP，最后再考虑画板。**
4. **里程碑与任务卡**：先定最小可跑闭环（机械臂 = 一个关节受控转动；小车 = 轮子听指令；盒子 = 屏亮并显示传感器值），倒推依赖，写成 mermaid（节点用纯文本标签）。里程碑 M0 定稿采购 → M1 通电自检 → M2 单模块能动 → M3 完整链路 → M4 自主创作，每个标"孩子的可见成果 / 家长工时 / 放弃条件"。
5. **拆任务卡 + 排课时**：一张卡 = 一次坐下 = ≤25 分钟一个动作单元，必含：目标（孩子能懂的一句话）/ 物料 / 三档分工 / 步骤（每步都有看得见的结果）/ 验收判据 / 失败兜底 / ⚠️ 安全。任务卡按里程碑归类进家长实现手册；课件按**课时**（45 分钟/课，10–14 页）另排一条线，**一课一个目录** `docs/儿童课程/第NN课-课题/`，每页带一句讲者备注即可。
6. **落盘与登记**：按 §6 产出工程文档 + 三份教学材料（位置见 §6.0），过 §9 自检，更新 `projects/README.md` 索引与 `CHANGELOG.md`。提交（仅当用户要求）：`docs(<slug>): 新增家长实现手册与儿童课程`。

## 3. 六维拆解框架

| 维度 | 拆出什么 | 对应目录 |
|---|---|---|
| ① 硬件电子 | 主控/驱动/传感器/电源/线束、供电与电流预算、接线端子表 | `hardware/` |
| ② 结构外壳 | 打印件清单与数量、承力件材料与填充、金属加工件、装配顺序 | `enclosure/` |
| ③ 固件 | 开发板、工具链版本、编译烧录命令、引脚定义、验证方法 | `firmware/` |
| ④ 上位机软件 | 系统要求、依赖版本、设备权限（USB/串口/CAN）、启动顺序 | `software/` |
| ⑤ 算法代码 | 算力与数据集、能否降级为固定动作演示、可视化入口 | `code/` |
| ⑥ 资料与生态 | 官方仓库/Wiki/视频/社区、许可限制、失效风险与本地存档 | `docs/99-参考资源.md` |

每维必答四问（缺一不可）：

1. **门槛**：最难的三件事是什么？需要什么技能（焊接/烧录/命令行/建模）？
2. **降级路径**：能否用"买成品 / 别人编译好的固件 / 社区代做"绕开？绕不开的写清外协渠道与费用量级。
3. **卡点**：最可能让人放弃的是什么（电源反接、驱动装不上、机械干涉、电机堵转）？给前置检查手段。
4. **实现路径**：这一维的东西**到底怎么做出来**（详见 §4），落到"件名 + 参数 + 谁做 + 多少钱 + 多久到"。

提取清单、判定标准、常见坑见 `references/拆解维度.md`。

## 4. 可实现路径（把"能做"变成"已下单/已做出"）

| 要什么 | 首选做法 | 落地参数要点 | 孩子参与 |
|---|---|---|---|
| 电路板 | 嘉立创：立创EDA 画原理图 → PCB → DRC → 导出 Gerber → 下单打样；元件用立创商城/嘉立创 BOM 配单 | 板厚 1.6mm、4 层以内、尺寸 ≤100×100mm 最便宜；需 SMT 时同时给 BOM + 坐标文件 | L1 选颜色/点数验收；L3 在 EDA 里挪一个元件 |
| 只想要功能，不想画板 | 洞洞板 + 杜邦线 / 成品模块堆叠 / 面包板 | 先跑通再固化；固定用热熔胶+尼龙柱 | L2 插线、对号 |
| 外壳结构件 | 嘉立创 3D 打印 / 淘宝代打：传 STL，选材料按克计价；急用先 FDM-PLA | 公差按 ±0.2mm 留量；受力件 PETG/尼龙 + 填充 ≥40% | L2 对件号点数；L3 调缩放与填充 |
| 亚克力/木板 | 激光切割代做：给 DXF/SVG | 孔位留 0.1–0.2mm 补偿 | L1 撕膜、对编号 |
| 线束端子 | 买成品线束 / 免焊端子；压接工具一次买对 | 写清线径、长度、端子型号、针序 | L2 按表插线 |
| 焊接、烧录、标定 | 找创客空间/社区代焊代烧；模块直接买"已烧录"版本 | 交付物 = 烧好的板 + 一句话验证方法 | 孩子只做验收与记录 |
| 机械金属件 | 买成品件优先；CNC/钣金给图纸外协 | 给 STEP + 材质 + 表面处理 | L1 收件核对 |

硬规则：

- **能买到的都不自制**；自制只保留"买不到且安全"的那部分。
- 任何外协件在文档里写：下单要点、价格量级、交期、收货验收动作。价格写量级并标注 `以页面为准（访问日期）`。
- 收到货先验收再开箱装配：PCB 目检虚焊/桥连、打印件量关键孔距、元件点数。
- 一页速查与下单检查表见 `references/可实现路径与外包.md`。

## 5. 让小朋友愿意做（游戏化 + 语言 + 节奏）

| 要素 | 做法 |
|---|---|
| 关卡化 | 里程碑改叫"第 N 关"，每关有通关条件；M4 = Boss 关（做给家人看） |
| 即时反馈 | 每关必有"看得见/听得到"的结果：灯亮、轮子转、屏幕出字，≤10 秒短视频存档 |
| 贴纸与徽章 | 每张卡完成盖一枚章；集齐 3 枚换一次"展示时刻"，集齐一关发一个称号（接线员→调试员→工程师） |
| 角色扮演 | 每张卡给孩子一个角色：材料管理员 / 记录员 / 装配工 / 质检员 / 工程师（轮换） |
| 语言 | 一句话 ≤12 字；术语先给外号再给正式名；用拟声词与拟人（"电机在使劲嗯嗯叫"） |
| 节奏 | 单卡 ≤25 分钟，一次坐 ≤2 张卡；先看见现象再讲原理；结束留一个"下次的钩子" |
| 选择权 | 给 A/B 两个都安全的选项让孩子选（颜色、位置、速度），不替他做决定 |
| 失败处理 | 失败改称"发现了一条线索"，写进线索表，下一张卡第一件事查它 |

三档参与度（同一项目不同环节可选不同档）：

| 档 | 孩子做什么 | 家长做什么 | 升档判据 |
|---|---|---|---|
| L1 观察 | 递零件、对编号、按按钮、说出看到的现象 | 全部动手 + 讲解 + 防护 | 能说清"这步在做什么、成功会看到什么" |
| L2 协作 | 拧螺丝、插线、插拔 USB、填验收表 | 把关极性与紧固、执行危险步骤 | 同类动作无提示也不出错 |
| L3 独立 | 看图纸独立做、改参数、记数据、讲原理 | 只做安全监护，容忍失败 | 能讲清"上次为什么失败、这次改了什么" |

危险动作（电烙铁、热熔胶枪、220V、锂电池充放电、上电抱闸、激光、高速旋转件、金属加工）一律家长单独执行，孩子只在安全距离外或以 L1 参与，任务卡里用 ⚠️ 单列。

详细语言模板、游戏化道具、情绪处理、知识卡五步法见 `references/儿童友好设计.md`；分档标准与安全红线见 `references/儿童适配与安全.md`。

三份教学材料的分工（不重复写同一件事）：

- **① 家长实现手册**：实现导向，**只写"怎么做到"**——买什么、怎么装、怎么验、卡住先查哪。少讲原理（原理进课件与知识卡）。每个文件都要能单独照着执行，不写"请自行查阅"。
- **② 儿童课程（课件）**：一课时一个目录，孩子看得懂的画面 + 图位；原理在这里讲。
- **③ 儿童知识卡**：一个术语/原理一张，给孩子带回家；**随课时分发**到该课 `知识卡/`。

### A. 工程规范文档（`projects/<slug>/docs/`，遵守 `docs/目录规范.md`）

增量补齐，已存在的先读再改：`01-项目简介.md`（是什么/教学价值/适龄段）、`02-选型与BOM.md`（版本差异、MVP 第一批 vs 后续、参考价、替代型号、渠道）、`03-组装与调试.md`（分步装配 + 接线图与端子表 + 通电自检 + 故障排查表）、`04-软件环境.md`（系统要求、依赖版本、一键脚本、驱动与权限坑）、`05-教学与课程.md`（课时安排、实验任务、考核点、教学产出索引）、`99-参考资源.md`。

### B. 家长实现手册（`projects/<slug>/docs/家长实现/`，六个文件固定）

`00-总纲与路线图.md`、`01-六维拆解总表.md`、`02-里程碑与任务卡.md`、`03-家长话术与提问卡.md`、`04-验收与展示.md`、`05-安全与工具采购清单.md`。骨架由 `scaffold_family_guide.sh` 生成。写法要求：**以"下一步做什么"为主，短句，能删就删**；原理、比喻、术语展开一律不在这里长篇讲解（放课件/知识卡），这里只留"一句话类比 + 指向哪张卡"。

### C. 儿童课程（`projects/<slug>/docs/儿童课程/`，按课时分目录）

一课一个目录，固定命名 `第NN课-课题/`，内含 `课件.md`（源）、`课件.html`（构建产物）、`图/`（配图）、`知识卡/`（本课发的卡）、`README.md`（课时卡）；`docs/儿童课程/README.md` 是课程总览（课时表 + 知识卡全集索引）。骨架由 `scaffold_teaching_materials.sh` 生成。

课件规则：**一页一件事、一页 ≤15 字、一页讲 1 分钟**；每页都要有图位（`![说明](图路径)`）和一句讲者备注（`<!-- notes: ... -->`）；照片放本课 `图/`（如 `第01课-课题/图/整机.png`），构建时自动内嵌。骨架见 `assets/课件模板/课件骨架.md`，样张与可放映示例见 `assets/课件模板/示例-第一课.md` 与其同名 `.html`。

### D. 儿童知识卡（`projects/<slug>/docs/儿童课程/第NN课-课题/知识卡/NN-主题.md`）

给孩子看的一页纸（可打印、可当贴纸底）。每张按五步走：**看到什么现象 → 先猜 → 动手验证 → 它叫什么（术语 + 生活类比）→ 还在哪里见过**。必含：大标题（≤8 字）、一句话解释（≤20 字）、图位、家里能做的小实验（不用买材料）、3 个追问、术语卡（正面外号/背面定义）。每个原理点至少 1 张，**随课时分发**到该课 `知识卡/`，六维里出现的术语不得有空卡。骨架见 `assets/知识卡模板.md`。

## 8. 写作硬规则

1. 每个文档头部三行：**适用版本 / 最后更新日期（`date +%F`）/ 前置条件**。
2. 每一步都要能回答"做完这步我**看得见**什么"，看不见的不算一步。
3. 危险步骤以 ⚠️ 单列：谁做、防护什么、出错怎么收场。
4. 接线**图和表同时给**（端子号 / 信号名 / 线色 / 对端 / 备注）。
5. 成本写人民币参考价 + 外协费；时间写**家长工时**，不是日历天。
6. 不写未验证的性能与安全宣传；宣传口径与实测口径分开，未实测标 `待验证`。
7. 术语首现处给"生活类比 + 一句话解释"，正文不再重复。不出现学生姓名/学校/联系方式、内网 IP、密钥、真实账号；第三方资料只登记"上游 + commit/tag + 本地改动"。
8. 交付时不留 `__` 占位与"待补"空段；确实缺的写成明确待办（缺什么、谁补、补到哪个文件）并告知用户。
