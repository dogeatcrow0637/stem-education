# 里程碑与任务卡（英语宠物怀表）

| 字段 | 值 |
|---|---|
| 适用版本 | 方案 v1.0（Waveshare ESP32-S3-Touch-AMOLED-1.75） |
| 最后更新 | 2026-11-13 |
| 前置条件 | 已读 `00-总纲与路线图.md`；材料已到货 |

**卡片规则**：一张卡 = 一次坐下 = 一个动作单元（≤25 分钟）；做完必须能看见结果并打勾。打勾格式：`- [x] 卡 M1-1`。每张卡完成盖一枚章，每 3 张卡安排一次「展示时刻」（拍照/录 ≤10 秒视频），每完成一个里程碑发一个称号（材料员→接线员→调试员→对话设计师→怀表工程师）。

## M0 定稿与采购

目标：型号定稿、MVP 物料到货、核对无缺件。

### 卡 M0-1：选版本与下单
- 目标（孩子视角）：「我们决定买哪一块表，把它请回家。」
- 物料：采购清单（`05-安全与工具采购清单.md`）
- 三档分工：L1 看图片说出「屏幕、麦克风、喇叭在哪」｜L2 对照清单点数量｜L3 做比较表（价格/是否触摸/是否带音频）并给结论
- 步骤：
  1. 打开 Waveshare 产品页，确认是 **1.75 英寸 AMOLED 触摸版**，记下是 1.75 还是 1.75C → 结果：写下一行型号
  2. 选电池（3.7V、带保护板、MX1.25）和 8Ω 喇叭 → 结果：订单里各 1 件
  3. 下单，保存订单截图 → 结果：截图归档到 `resources/`
- 验收判据：型号、电池、喇叭三项都有明确订单；版本不含糊
- 失败兜底：缺货 → 换同系列或分两家买；不确定版本 → 先问客服要丝印照片
- ⚠️ 安全：不买无保护板的裸电芯；不买需要自己焊线的裸喇叭（除非家长会焊）

### 卡 M0-2：到货核对
- 目标：「所有零件都到齐，一个都不少。」
- 物料：BOM + 分格收纳盒
- 三档分工：L1 报出零件名｜L2 点数并分格｜L3 记录缺件/错件并拍开箱照
- 步骤：
  1. 逐项对照 BOM 打勾 → 结果：清单完成
  2. 电池用万用表量电压（约 3.7–4.2V），看插头红黑顺序 → 结果：记下电压与极性
  3. 分格收纳并拍一张全家福 → 结果：照片
- 验收判据：无未处理缺件；电池极性已确认
- 失败兜底：缺件先做不依赖它的卡；电池异常直接联系商家，不要上电

## M1 屏幕与声音

目标：屏幕亮、触摸有反应、喇叭有测试音，孩子第一次看到「它活了」。

### 卡 M1-1：桌面最小系统
- 目标：「只插一根线，看它亮不亮。」
- 物料：开发板、能传数据的 USB-C 线
- 三档分工：L1 在安全距离外说看到什么｜L2 在口令下插拔 USB｜L3 自己插线并读串口设备名
- 步骤：
  1. 只接 USB，不接电池/喇叭 → 结果：屏幕亮或串口能识别
  2. 电脑设备列表出现串口（`/dev/tty.usbmodem*` 或 `COMx`）→ 结果：记下端口名
- 验收判据：屏幕有反应 + 电脑能识别串口
- 失败兜底：无反应 → 换线、换口、换电脑；仍无 → 联系卖家
- ⚠️ 安全：此卡不接电池；板子放绝缘桌面

### 卡 M1-2：烧官方 demo，逐个验硬件
- 目标：「屏幕、触摸、麦克风、喇叭，一个一个确认没坏。」
- 物料：ESP-IDF、Waveshare 官方 demo
- 三档分工：L1 看屏幕变化并说出「花了/没花」｜L2 按口令点屏幕四角｜L3 独立烧录并记录结果
- 步骤（每烧一个只验一件事）：
  1. `05_LVGL_WITH_RAM` → 屏幕显示示例、不花屏
  2. 触摸 demo → 点四角与中心，位置准确
  3. `06_I2SCodec` → 接喇叭，听到测试音；对话筒说话，串口有电平变化
- 验收判据：三项全过，各拍 5 秒视频
- 失败兜底：花屏 → 选对 1.75/1.75C 配置；触摸偏 → 重烧/查排线；无声 → 查 PA 使能与喇叭
- ⚠️ 安全：音频测试音量先调低；喇叭不要贴耳

### 卡 M1-3：接喇叭与电池（家长单独执行）
- 目标：「拔掉 USB 也能开机。」
- 物料：喇叭、电池、万用表
- 三档分工：L1 在安全距离外看并说出「红灯/绿灯」｜L2 家长口令下递工具｜L3 复述一遍上电检查项
- 步骤：
  1. 断电状态核对电池极性（红正黑负）→ 结果：与板子丝印一致
  2. 先接喇叭，再接电池 → 结果：拨开关能开机
  3. 插 5V/1A 充电头，看充电指示 → 结果：电量上升、不烫
- 验收判据：离 USB 能开机；充电 10 分钟不发烫
- 失败兜底：不开机 → 量电池电压/查开关；发烫/异味 → 立即拔电池
- ⚠️ 安全：**本卡只由家长操作**；不用快充头；电池不折叠不挤压；孩子不碰电池插头

## M2 烧录与联网

目标：装上「小脑」，让设备连上 Wi-Fi 和服务端。

### 卡 M2-1：装 ESP-IDF
- 目标：「电脑学会跟这块板说话。」
- 物料：电脑、网络
- 三档分工：L1 看进度条｜L2 帮按回车｜L3 自己复制命令并检查 `idf.py --version`
- 步骤：
  1. 按 `04-软件环境.md` 克隆 ESP-IDF `release/v6.1` → 结果：`./install.sh esp32s3` 成功
  2. `. ./export.sh` → `idf.py --version` 显示 v6.1.x → 结果：版本正确
- 验收判据：命令能跑，版本 ≥6.0.1
- 失败兜底：网络慢 → 换镜像/重试；权限错 → 不要 sudo 混用
- ⚠️ 安全：—

### 卡 M2-2：烧自研固件 V0.1（Wi-Fi + OTA）
- 目标：「板子先能自己上网、自己检查升级。」
- 物料：本仓库 `firmware/`、ESP-IDF
- 三档分工：L1 复述「烧进去的是我们自己写的固件」｜L2 插拔线｜L3 独立完成 menuconfig
- 步骤：
  1. `cd projects/english-pet-watch/firmware && idf.py set-target esp32s3` → 结果：target 设置成功
  2. `idf.py menuconfig` → `English Pet Watch` 填 Wi-Fi、型号、OTA 地址 → 结果：配置能保存
  3. `idf.py build` → `idf.py -p <口> flash monitor` → 结果：串口出现启动日志
- 验收判据：串口出现 `获得 IP` 和 `当前已是最新固件`
- 失败兜底：编译错 → 检查 ESP-IDF 版本；烧录失败 → 按住 BOOT 再点 RST；反复重启 → 换 USB 口/查供电
- ⚠️ 安全：烧录时断开电池（用 USB 供电），避免边充边刷
- 说明：V0.1 还没有语音；「会聊天」在 V0.2 完成后验证

### 卡 M2-3：配网并验证 OTA
- 目标：「它找到回家的路（服务端），还能自己升级。」
- 物料：电脑（服务端）、USB 线
- 三档分工：L1 念 Wi-Fi 名字｜L2 在 menuconfig 输入密码｜L3 自己发布一版固件并验证升级
- 步骤：
  1. 在 menuconfig 填 2.4GHz Wi-Fi → 结果：设备日志显示 `获得 IP`
  2. 把 OTA 地址设为 `http://<服务端IP>:8003/xiaozhi/ota/` → 结果：设备请求 OTA 成功
  3. 改版本号、`idf.py build`、运行 `tools/publish_firmware.sh` → 结果：设备自动升级并重启
  3. 电脑 `ping <设备IP>` → 结果：能通
- 验收判据：设备日志出现 WebSocket 连接成功
- 失败兜底：连不上 → 确认同一路由器、关防火墙、检查 IP；5GHz-only → 开 2.4G
- ⚠️ 安全：不要把 Wi-Fi 密码/密钥写进仓库或截图

## M3 英语老师上线

目标：说 Hello，3 秒内英语回应，可打断。

### 卡 M3-1：起服务端
- 目标：「电脑里住一位会英语的老师。」
- 物料：Docker、xiaozhi-esp32-server、云服务 Key
- 三档分工：L1 看日志找「8000/8003」｜L2 帮复制 IP｜L3 独立改 `.config.yaml`
- 步骤：
  1. 按 `04-软件环境.md` 下载 compose/config、放模型 → 结果：目录结构正确
  2. `docker compose up -d` → 结果：日志出现 OTA 与 WebSocket 地址
  3. 配 ASR/LLM/TTS 与 Prompt → 结果：`.config.yaml` 有 `selected_module` 和英语老师 Prompt
- 验收判据：日志无报错；浏览器/`curl` 能访问 OTA 地址
- 失败兜底：缺模型 → 补 `model.pt`；端口占用 → 改端口；Key 错 → 看供应商控制台
- ⚠️ 安全：Key 只放本机 `.config.yaml`，不提交、不发群

### 卡 M3-2：第一次英语对话
- 目标：「我说 Hello，它用英语回我。」
- 物料：设备、服务端
- 三档分工：L1 说 Hello｜L2 记录「说完到出声」秒数｜L3 看日志指出 ASR/LLM/TTS 三段
- 步骤：
  1. 触摸/按键说话，说 "Hello" → 结果：服务端日志出现识别文本
  2. 听回复 → 结果：3 秒内出声
  3. 在它说话时插话 → 结果：它停下并听你
- 验收判据：连续 3 次成功；打断有效
- 失败兜底：没识别 → 查麦克风/ASR；没声音 → 查 TTS/音量；延迟高 → 换近的供应商/缩短回复
- ⚠️ 安全：音量 ≤70%；每次 ≤15 分钟

### 卡 M3-3：调 Prompt 与对话脚本
- 目标：「让它更像英语老师，而不是闲聊机器人。」
- 物料：`software/prompts/english-teacher.md`
- 三档分工：L1 选今天聊「动物」还是「食物」｜L2 一起改一句规则｜L3 独立改 Prompt 并对比前后
- 步骤：
  1. 记录原始回答（录 10 秒）→ 结果：基线
  2. 只改一条规则（如「每次最多 2 个新单词」）→ 结果：新回答变短
  3. 写下 5 句情景对话脚本 → 结果：脚本文件
- 验收判据：孩子能说出「改了什么、为什么变了」
- 失败兜底：越改越乱 → 一次只改一条；改坏 → 恢复上一版
- ⚠️ 安全：不写孩子真实姓名/学校进 Prompt

## M4 装壳与展示

目标：合上怀表壳，能连续用 30 分钟，并讲清 3 分钟。

### 卡 M4-1：装壳
- 目标：「它变成一块真正的怀表。」
- 物料：打印壳、螺丝、双面胶、挂绳
- 三档分工：L1 对件号｜L2 拧螺丝/贴胶｜L3 独立干装并记录干涉点
- 步骤：
  1. 干装（不锁螺丝），确认屏幕/触摸/USB-C/喇叭孔/麦克风孔对齐 → 结果：能合上
  2. 天线区域留空，不贴电池 → 结果：合壳后 Wi-Fi 仍能连
  3. 锁壳、挂绳 → 结果：整机不晃、不夹线
- 验收判据：合壳后屏幕/触摸/麦克风/喇叭/充电/联网全部正常
- 失败兜底：装不进 → 修壳/换纸板壳；信号差 → 开天线窗/移电池
- ⚠️ 安全：装壳前断电；电池用双面胶固定，不压在螺丝下

### 卡 M4-2：续航与充电
- 目标：「知道它能用多久，怎么充电才安全。」
- 物料：秒表、充电头
- 三档分工：L1 报时间｜L2 记录每 10 分钟电量｜L3 做续航表并画柱状图
- 步骤：
  1. 满电，连续对话到自动关机 → 结果：总时长
  2. 息屏看时间模式跑 1 小时 → 结果：耗电百分比
  3. 用 5V/1A 充电，记录充满时间与最高温度 → 结果：充电记录
- 验收判据：有 3 组数据；充电不烫手
- 失败兜底：续航太短 → 降亮度/换更大电池/减少常连；充电烫 → 停用换充电头
- ⚠️ 安全：充电时人不要离开太久；鼓包立即停用

### 卡 M4-3：3 分钟展示
- 目标：「这是我做的，我能讲明白。」
- 三档分工：L1 说 3 句话｜L2 演示 + 1 分钟｜L3 独立 3 分钟（按 `04-验收与展示.md` 脚本）
- 步骤：按脚本讲「是什么/怎么做/最难/还想改」→ 结果：录视频
- 验收判据：能回答「没网会怎样」「语音去哪了」「为什么不能一直聊」
- 失败兜底：忘词 → 看一页提示卡；设备故障 → 放提前录好的演示视频
- ⚠️ 安全：展示时音量适中；不展示 API Key 与 Wi-Fi 密码
