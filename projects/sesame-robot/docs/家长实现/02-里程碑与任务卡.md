# 里程碑与任务卡（Sesame Robot 迷你四足机器人）

| 字段 | 值 |
|---|---|
| 适用版本 | 上游 `main` @ `f328ed3`；硬件 S2 Mini 手接线（MVP） |
| 最后更新 | 2026-11-05 |
| 前置条件 | 已读 `00-总纲与路线图.md`；材料已到货 |

**卡片规则**：一张卡 = 一次坐下 = 一个动作单元（≤25 分钟）；做完必须能看见结果并打勾。打勾格式：`- [x] 卡 M1-1`。每张卡完成盖一枚章，每 3 张卡安排一次"展示时刻"（拍照/录 ≤10 秒视频），每完成一个里程碑发一个称号（材料员→接线员→调试员→工程师）。

## M0 定稿与采购

目标：型号定稿、MVP 物料到货、核对无缺件。

### 卡 M0-1：选版本与下单
- 目标（孩子视角）："我们决定买哪一套，把它请回家。"
- 物料：采购清单（见 `05-安全与工具采购清单.md`）
- 三档分工：L1 一起看图片/视频并说出选哪个｜L2 一起对照清单点数量｜L3 孩子做比较表（价格/难度）并给结论
- 步骤：
  1. 看官方演示视频 → 结果：孩子能说出"我们要做的是这个"
  2. 对照版本对比表选型（S2 Mini 手接线 / V3.1 成品）→ 结果：写下一行结论（版本 + 理由）
  3. 同时发 3D 打印 → 结果：打印订单截图（打印最花日历时间，先发）
  4. 下单电子件与舵机 → 结果：订单截图存档
- 验收判据：清单每一项都有"已下单/替代型号"状态；打印已单独下单
- 失败兜底：缺货 → 换替代型号或分两家买；不想焊接 → 改选 V3.1 成品板
- ⚠️ 安全：—

### 卡 M0-2：到货核对
- 目标："所有零件都到齐，一个都不少。"
- 物料：采购清单 + 分格收纳盒 + 标签纸
- 三档分工：L1 报出零件名｜L2 点数并分格收纳｜L3 记录缺件与错件
- 步骤：
  1. 逐项核对 22 行 BOM → 结果：清单全部打勾
  2. 10 个舵机分别贴 S0–S7 + 2 个"备用" → 结果：标签两端一致
  3. 打印件清点 11 件 → 结果：框架、上下盖、8 个关节齐全
  4. 分格收纳 → 结果：照片一张
- 验收判据：无未处理缺件（缺件已联系商家）；舵机型号确认为 **MG90S 金属齿 180°**
- 失败兜底：缺件先做不依赖它的里程碑；舵机买错角度 → 立即退换，不要将就
- ⚠️ 安全：—

## M1 通电自检

目标：供电正常、无短路，孩子看到"活的"第一眼反馈。

### 卡 M1-1：结构粗装与固定
- 目标：把机器立起来、固定住，不会自己倒/掉。
- 物料：11 个打印件、M2×5 自攻螺丝约 40 颗、精密十字螺丝刀
- 三档分工：L1 递件对号｜L2 拧螺丝（家长把关力矩）｜L3 独立照图装
- 步骤：
  1. 清支撑、按 L/R 与 R1–R4/L1–L4 分件 → 结果：11 件排开、无混淆
  2. 8 个舵机塞入关节壳（舵机轴朝外，线从侧槽出）→ 结果：舵机与壳齐平不晃
  3. 内部框架与底盖干装 → 结果：框架能立住不晃
  4. 固定线束 → 结果：极限姿态不夹线
- 验收判据：螺丝紧固不过拧（塑料孔滑牙即停）；关节能套进舵机而不需暴力敲击；上下盖能扣上
- 失败兜底：孔位偏紧 → 轻回牙或换铜螺母；镜像件装反 → 对照 `enclosure/print-notes.md` 重装
- ⚠️ 安全：拆装前断电；螺丝不要顶到舵机内部

### 卡 M1-2：首次上电
- 目标：灯亮、OLED 亮、WiFi 热点出现，说明电走到了。
- 物料：5V/3A USB-C 充电头与数据线、万用表、S2 Mini、OLED
- 三档分工：L1 在安全距离外看并说出看到什么｜L2 家长口令下按住电源开关｜L3 自己按顺序上电并口述检查项
- 步骤：
  1. 断电状态用万用表查 5V 轨对 GND → 结果：蜂鸣档不响（无短路）
  2. 降压模块空载调压 → 结果：输出 5.1V
  3. 只接主控与 OLED 上电 → 结果：S2 Mini 灯亮、OLED 亮
  4. 等 10–20 秒 → 结果：手机搜到 `Sesame-Controller-BETA`
- 验收判据：出现预期反馈且无发烫、异味、异响；热点能出现
- 失败兜底：无反应 → 查 USB 线是否传数据/板型/5V；发烫或异味 → 立即断电，查焊桥
- ⚠️ 安全：上电前清空运动范围、机身固定、手离开运动区域；首次上电不接舵机

## M2 单模块能动

目标：一个舵机受控动作，孩子第一次看到"我让它动它就动"。

### 卡 M2-1：烧录/配置固件
- 目标：板子装上"小脑"。
- 物料：S2 Mini、USB-C 数据线、Arduino IDE 2.x、上游固件 `f328ed3`
- 三档分工：L1 看着并复述"烧进去的是什么"｜L2 在口令下插拔线｜L3 独立照文档烧录
- 步骤：
  1. 装 ESP32 板支持与三个库（`ESP32Servo` **3.0.9**、Adafruit SSD1306、Adafruit GFX）→ 结果：库管理器显示版本正确
  2. 板型选 **LOLIN S2 Mini**，`USB CDC On Boot = Enabled`，上传速度 921600 → 结果：端口能识别
  3. 启用 S2 Mini 引脚表，注释掉 V1/V2/V3 配置 → 结果：编译通过
  4. 上传 → 结果：串口 115200 出现启动日志
- 验收判据：串口出现启动日志且无重启循环；WiFi 热点出现
- 失败兜底：串口被占用 → 关掉上位机/串口监视器；识别不到板 → 换数据线、按住 BOOT 再上传；库版本被升级 → 卸载重装 3.0.9
- ⚠️ 安全：烧录前断开舵机电源

### 卡 M2-2：让一个舵机动起来
- 目标："我发命令，它动一下。"
- 物料：单个已编号舵机、5V/3A 电源、Web 控制页或串口
- 三档分工：L1 按按钮｜L2 按口令发指令并记录现象｜L3 自己改一个角度（0°/90°/180°）看变化
- 步骤：
  1. 只接 S0 一个舵机 → 结果：上电不重启
  2. 网页点单舵机测试，发 0°/90°/180° → 结果：舵机顺滑走完 180°（录 ≤10 秒视频）
  3. 换成 S1–S7 逐个测试 → 结果：每个都能动，记录异响/发热个体
- 验收判据：动作方向、幅度与预期一致；无堵转异响；10 个舵机中至少 8 个合格
- 失败兜底：不动 → 查供电/使能/接线编号；抖动或异响 → 降速度、空载复测、换备件
- ⚠️ 安全：手不进入运动范围；异常立即断电；不强行掰舵机

## M3 完整链路

目标：上位机 → 固件 → 硬件的完整通路跑通，能做一次"一键演示"。

### 卡 M3-1：上位机连通
- 目标：电脑/手机能识别并控制设备。
- 物料：手机或电脑（2.4GHz WiFi）、浏览器；可选 `curl`/Python
- 三档分工：L1 看图说出"线和电脑接上了"｜L2 连热点/打开网页｜L3 自己跑 `curl` 并读返回 JSON
- 步骤：
  1. 连 `Sesame-Controller-BETA`（密码 `12345678`）→ 结果：手机显示已连接
  2. **关闭手机移动数据** → 结果：浏览器能打开 `http://192.168.4.1`
  3. 打开控制页 → 结果：界面出现按钮与状态
  4. `curl http://192.168.4.1/api/status`（可选）→ 结果：返回含 `currentCommand` 的 JSON
- 验收判据：设备连通、控制页可操作；API 返回 `status: ok`
- 失败兜底：权限/驱动/网络问题 → 按 `04-验收与展示.md` 排查顺序逐条查；`sesame-robot.local` 不解析 → 直接用 IP
- ⚠️ 安全：固件无鉴权、无 HTTPS，只连可信局域网，不接公网

### 卡 M3-2：校准并让它站好
- 目标：四腿呈镜像 X 形，稳定站 30 秒。
- 物料：Web 控制页、M2.5×5 机械螺丝、小十字螺丝刀
- 三档分工：L1 喊"停/站"口令并观察｜L2 点按钮、递螺丝｜L3 独立完成 REST/STAND 校准
- 步骤：
  1. 拆下四个髋关节盘，舵机轴自由 → 结果：舵机能自由转
  2. 网页点 **Standby** 初始化 PWM → 结果：舵机到中位
  3. 逐个插舵机，确认方向正确 → 结果：插一个动一个，不串扰
  4. 点 **Rest**，髋关节到 90°，压上髋盘与机身平行 → 结果：四腿与机身平行
  5. 点 **Stand**，四腿各转 45° → 结果：镜像 X 形
  6. 回 **Rest** 复查，锁 M2.5 中心螺丝 → 结果：再切两次姿态仍不偏
- 验收判据：`REST` 平行、`STAND` 镜像 X、站立 30 秒不塌
- 失败兜底：某条腿方向反 → 90% 是插错编号，先查 S0–S7；干涉/异响 → 立即断电重装
- ⚠️ 安全：校准前**不能锁关节**；手不进入运动范围；异常立即断电

### 卡 M3-3：一键演示
- 目标：全套动作一次跑通并录屏。
- 物料：Web 控制页、手机支架（可选）
- 三档分工：L1 当解说员｜L2 点击启动并观察｜L3 独立执行整个流程
- 步骤：
  1. 点 `stand` → 结果：稳定站起
  2. 点 `forward` 走 5 秒 → 结果：向前走不摔
  3. 点 `left` / `right` 各转一次 → 结果：能转向
  4. 点 `wave` + 开心表情 → 结果：挥手、OLED 变脸
  5. 点 `stop` → 结果：停住不抖
- 验收判据：连续 2 次完整演示成功（录屏存档）
- 失败兜底：偶发失败 → 记录现象、降低速度/幅度重试；走两步就断 → 查电源余量与 `motorCurrentDelay`
- ⚠️ 安全：演示时人与机器保持一臂距离

## M4 自主创作

目标：孩子提出并实现一个小改动，形成"这是我改的"归属感。

### 卡 M4-1：改一个参数
- 目标：改动前后有可比较的差异。
- 物料：Web 控制页 Settings / `code/api-examples/`
- 三档分工：L1 选"改哪个、变大还是变小"｜L2 一起改并观察｜L3 独立改并解释原理
- 步骤：
  1. 记录原始值（`frameDelay=120`、`walkCycles=15`、`motorCurrentDelay=25`）→ 结果：写进验收表
  2. 只改一个参数，例如 `frameDelay` 120→200 → 结果：走路变慢但更稳
  3. 对比前后视频 → 结果：对比记录（数字/照片）
- 验收判据：孩子能说出"改了什么、为什么变了"
- 失败兜底：改完更差 → 先恢复默认值，再一次只改一个变量
- ⚠️ 安全：改参数不改变运动范围上限；异常立即 `stop`

### 卡 M4-2：加一个功能 / 讲给别人听
- 目标：把作品讲清楚，成为"作者"。
- 物料：展示脚本（`04-验收与展示.md`）、可选 Python 脚本
- 三档分工：L1 说 3 句话介绍｜L2 演示 + 说 1 分钟｜L3 独立做 3 分钟讲解（按展示脚本）
- 步骤（选一个）：
  1. 用 `code/api-examples/demo.py` 定时发 `wave`，做成"放学提醒" → 结果：到点自动挥手
  2. 用 Sesame Studio 做 3 帧动作，粘贴生成的 C++ 角度 → 结果：新动作能复现
  3. 只排练展示：是什么 / 怎么做 / 最难在哪 / 下一步 → 结果：3 分钟讲解
- 验收判据：能回答"哪里最难、怎么解决的"；改动可复现
- 失败兜底：功能改不动 → 只做展示排练，不影响结课
- ⚠️ 安全：涉及重新烧录时断开舵机电源
